## 三、核心结论速览

- **一句话目标**：用机器学习替代人工经验，预测直播场景下的销量波动，并翻译为供应链可执行的三级备货策略。
- **模型选型**：分阶段演进 —— 第一阶段 LightGBM（主力）+ XGBoost（对照）；第二阶段引入 SaleNet / TFT（直播行为数据积累后）。
- **关键指标**：直播日 R² 0.736、方向准确率 63.3%、日常天 MAPE ~15%（优于人工基线 ~40%）。
- **落地抓手**：三级备货（保底量/期望量/冲刺量）对应自有产线/自有+外包/长周期物料，把"预测一个数"升级为"直接告诉供应链怎么备货"。

## 五、版本管理

本项目以**持续进化**的方式迭代，当前全部内容定义为 **第一版（v1.0.0）**，作为后续演进的基线。

| 版本 | 日期 | 内容范围 | 说明 |
|---|---|---|---|
| **v1.0.0**（第一版） | 2026-09-07 | 选型探索 + 技术方案 + 调研参考 + 需求定义 + 可运行 Demo | 从原始项目提取的可广泛化复用基线，剥离企业/访谈绑定材料 |

**演进约定：**

- **版本号**：遵循 `主版本.次版本.修订号`（Semantic Versioning）。
  - `主版本`：研究方向或整体架构发生重大变更（如引入全新预测范式）。
  - `次版本`：新增/重构某一模块（如新增模型、新增数据源、扩充文献）。
  - `修订号`：文档勘误、参数微调、修复。
- **变更记录**：每次进化在 `CHANGELOG.md` 中登记，说明「改动了什么 / 为什么改 / 影响哪些文件」。
- **版本快照**：重大版本可通过 Git 分支/标签（`v1.0.0` 等）留档，便于回溯对比。
- **定义标准**：第一版以「可独立复用、可运行、可复现」为验收标准；后续版本在此基础上增量扩展。

> 详细变更历史见 `CHANGELOG.md`。

### 每次进化（发版）操作步骤

1. **改内容**：新增/修改文件，完成本次迭代的实质变更。
2. **登记变更**：在 `CHANGELOG.md` 顶部新增 `## [vX.Y.Z] — YYYY-MM-DD` 条目，记录「新增 / 变更 / 影响」。
3. **升版本号**：将 `VERSION` 文件更新为新的 `X.Y.Z`。
4. **同步页脚**（可选）：若属主版本/次版本，将各文档页脚的 `vX.Y.Z（第N版）` 与日期同步更新。
5. **提交**：
   ```bash
   git add -A
   git commit -m "chore: 发布 vX.Y.Z <一句话说明>"
   ```
6. **打标签**：
   ```bash
   git tag -a vX.Y.Z -m "第N版（vX.Y.Z）：<一句话说明>"
   ```
7. **推送**（已配置远程仓库时）：
   ```bash
   git push origin main --tags
   ```
