# LiveGMV 直播销量预测系统 — Dashboard 功能介绍

> **访问地址**：http://localhost:8501
>
> **技术栈**：Streamlit + LightGBM + XGBoost + SHAP + Python
>
> **面向对象**：供应链管理方向导师、学院领导、项目评审专家

---

## 一、系统概述

LiveGMV Dashboard 是一个面向直播电商供应链的**智能销量预测与决策辅助系统**。系统以仿真数据为基础，采用 LightGBM 与 XGBoost 集成学习算法，实现对直播场景下高波动销量的动态预测，并将预测结果翻译为可直接指导生产排程的**三级备货策略**。

整个 Dashboard 包含四大功能模块，通过左侧导航栏切换访问。

---

## 二、模块一：Overview（系统总览）

### 功能定位
项目入口页，用于快速了解系统整体架构和数据特征。

### 核心内容

| 组件 | 说明 | 面向谁 |
|---|---|---|
| **4 个指标卡片** | 数据源(6)、特征数(44)、模型数(3)、输出项(4) | 领导：一眼看懂项目规模 |
| **数据概览折线图** | 500 天仿真销量时间序列，灰色日常销售 + 红色标注直播日 | 老师：直观理解直播日脉冲特征 |
| **日均销量对比** | 非直播日均 ~3,200 件 vs 直播日均 ~63,000 件（约 20 倍） | 评审：数据符合真实业务场景 |
| **Top 10 特征重要性** | LightGBM 内置特征重要性横向条形图 | 技术专家：模型依赖哪些信号 |

### 业务价值
帮助评审在 30 秒内建立"数据长什么样 → 挑战在哪 → 模型怎么应对"的完整认知。

## 三、模块二：Predict & Explain（预测与解释）

### 功能定位
**系统的核心模块**，演示模型对单一样本的预测能力及预测依据。

### 交互方式
- **样本选择滑块**：在 98 个测试样本中任意切换，实时查看预测结果
- 所有图表和数据自动随滑块位置更新

### 核心内容

| 组件 | 说明 |
|---|---|
| **4 个结果卡片** | 实际销量 / 预测销量 / 误差百分比 / 日期类型（直播日/普通日） |
| **80% 置信区间** | 基于残差标准差计算，展示预测的不确定性范围 |
| **全量预测对比图** | 测试集 98 个样本的预测值与实际值双折线对比，蓝色阴影为 80% 置信带，红色星标为直播日 |
| **SHAP 瀑布图** | 针对当前样本的**逐特征贡献度分解**：红色柱表示"推动预测上调"的因素，蓝色柱表示"推动预测下调"的因素 |

### 业务价值

**场景**：供应链计划员在使用系统时，某次预测显示明天需要备货 8,000 件。系统自动展示：

```
预测上调因素（红色）：
  ↑ traffic × is_live_day  贡献 +3,200
  ↑ discount = 0.35        贡献 +1,800
  ↑ anchor_fans = 8,000    贡献 +1,100

预测下调因素（蓝色）：
  ↓ competitor_discount    贡献 -2,100
  ↓ sales_lag_7            贡献 -900
```

计划员可以立即判断：预测偏高的主要原因是明天有直播且折扣力度大，但竞品也在打折分流。这一机制将机器学习从"黑箱预测"升级为"可审计决策"，是面向企业落地的关键功能。

## 四、模块三：Inventory Plan（三级备货策略）

### 功能定位
将模型输出的预测值翻译为供应链可执行的备货方案。

### 交互方式
- **样本数量滑块**：控制展示 4-12 个样本

### 三级策略体系

| 层级 | 计算公式 | 生产方式 | 适用场景 |
|---|---|---|---|
| 🟢 **保底量** | P50 − 1.28σ | **自有产线** | 确定性较高，不外包不加班 |
| 🔵 **期望量** | P50（中位数预测） | **自有 + 外包** | 基准方案，预留外包产能弹性 |
| 🟠 **冲刺量** | P50 + 1.28σ | **仅备长周期物料** | 不提前生产成品，但锁定包材、粒子等长交期物料 |

### 核心内容

| 组件 | 说明 |
|---|---|
| **三级备货柱状图** | 每个样本三根柱（绿/蓝/橙）+ 红色星标（实际值），直播日样本标注 [LIVE] |
| **备货策略明细表** | 表格列出实际值、保底量、期望量、冲刺量、弹性区间 |

### 业务价值

传统预测只输出一个数字（如"预计卖 5,000 件"），计划员拿到后还需要自己判断"该备多少"。本系统直接输出三级方案，与供应链的实际决策层级一一对应：

- 保底量 → 工厂排产指令
- 期望量 → 产能预留决策
- 冲刺量 → 采购预警信号

这一设计使预测模型从"分析师工具"升级为"决策辅助系统"。

## 五、模块四：Model Comparison（模型对比）

### 功能定位
展示集成策略中各子模型的表现差异，证明集成学习的必要性和有效性。

### 核心内容

| 组件 | 说明 |
|---|---|
| **四模型预测对比** | LGB P50 / LGB P75 / XGB P50 / Ensemble 四张子图并排，各自与真实值对比 |
| **特征重要性对比** | LightGBM 与 XGBoost 的 Top 特征横向对比条形图 |

### 业务价值

- 证明 P75 模型（上四分位数）在直播日的预测值系统性高于 P50，解释了"为什么用 P75 而非 P50 做直播日预测"
- 展示 LightGBM 和 XGBoost 对特征的侧重不同，说明集成可以互补降方差
- 供技术评审验证模型设计的方法论合理性

## 六、侧边栏实时指标面板

固定显示的 4 个核心指标，贯穿所有页面：

## 七、技术特性（供技术评审参考）

| 特性 | 实现方式 |
|---|---|
| **类不平衡处理** | 直播日样本权重 8× |
| **分位数回归** | P50（中位数）+ P75（上四分位数）双模型 |
| **交互特征** | 6 个 is_live_day 交叉特征，区分直播日弹性 |
| **模型可解释性** | SHAP TreeExplainer，逐样本瀑布图 |
| **不确定性量化** | 残差标准差 1.28σ 计算 80% 置信区间 |
| **首次加载缓存** | Streamlit @st.cache_resource，模型训练仅执行一次 |
| **时序拆分** | 前 80% 训练 / 后 20% 测试，不随机打乱防数据泄露 |

## 八、系统运行说明

```bash
# 初始化（首次）
cd sales-prediction-demo
pip install streamlit lightgbm xgboost shap pandas numpy matplotlib scikit-learn

# 启动
streamlit run app.py --server.port 8501

# 浏览器访问
http://localhost:8501
```

首次启动需要训练 3 个模型（1-2 分钟），后续访问使用缓存秒开。
