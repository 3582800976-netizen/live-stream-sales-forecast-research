# 仿真数据生成说明

> **数据性质**：基于领域知识的合成数据（Domain-Knowledge-Driven Synthetic Data）
>
> **数据来源**：对某头部美妆集团供应链负责人的深度访谈（2026年7月），提炼业务规则后参数化生成
>
> **使用原因**：企业真实销售数据涉密无法获取，仿真数据可验证模型逻辑且生成过程完全透明可解释

---

## 一、数据概览

| 指标 | 数值 | 说明 |
|---|---|---|
| 总天数 | 200 天 | 约 7 个月 |
| 直播日数 | 19 天 | 约每 10-14 天一次 |
| 非直播日均销量 | 3,107 单 | 日常基线 |
| 直播日均销量 | 116,016 单 | 约 37× 脉冲 |
| 直播日峰值 | 291,518 单 | 约 94× 脉冲 |
| 特征维度 | 10 个输入特征 | 详见下文 |
| 目标变量 | `sales`（实际销量） | 连续值回归任务 |

## 二、生成公式与访谈依据

### 规则 1：日常销量基线

**生成公式**：
```
base = BASE_SALES + N(0, SALES_NOISE)
其中 BASE_SALES = 3000, SALES_NOISE = 800
```

| 访谈依据 | 访谈原话/场景 |
|---|---|
| 企业日常稳定出货，但存在自然波动 | "平时日发货 5 万件是常态"（按多 SKU 分摊，单 SKU 约数千） |
| 销量不是恒定值，有天-天随机性 | 快消品受天气、竞品促销、社交传播等不可控因素影响 |

**正态分布假设**：中心极限定理下，大量独立因素的叠加效应趋近正态分布，是销量预测领域的标准假设（参考 ARIMA 模型的白噪声假定）。

---

### 规则 2：节假日/周末效应

**生成公式**：
```
if is_holiday:  base *= rand(1.3, 2.0)
elif is_weekend: base *= rand(1.1, 1.4)
```

| 访谈依据 | 访谈原话/场景 |
|---|---|
| 平台大促期销量远超日常 | "判断该直播场次是否赶上 618、双11 或百亿补贴，该因素常导致预测偏差 ±30%" |
| 周末用户观看时长和下单意愿更强 | 行业常识：直播电商周末 DAU 和 GMV 普遍高于工作日 |

---

### 规则 3：价格需求弹性

**生成公式**：
```
discount_effect = 1 + (1 - discount) × 2.5
```

**参数说明**：弹性系数 2.5 表示折扣每增加 10%（如从 7 折变 6 折），销量提升约 25%。

| 访谈依据 | 访谈原话 |
|---|---|
| 消费者对价格敏感 | "便宜就会买" |
| 折扣力度直接影响转化率 | 访谈中提到需计算"不同折扣力度（99元 vs 89元）对应的转化率变化曲线" |

**经济学理论支撑**：价格需求弹性（Price Elasticity of Demand）是微观经济学基本模型。快消品通常弹性 > 1（富有弹性），2.5 处于日化/美妆行业合理区间（参考：Nijs et al., 2001, *The Category-Demand Effects of Price Promotions*）。

---

### 规则 4：竞品替代效应

**生成公式**：
```
competitor_effect = 1 - (1 - competitor_discount) × 0.8
```

**参数说明**：系数 0.8 < 自折扣系数 2.5，表示竞品打折对自身销量的负面影响，但强度弱于自身打折的正向拉动。

| 访谈依据 | 访谈原话 |
|---|---|
| 竞品直播同期降价会分流消费者 | "竞品突然降价打价格战" |
| 竞品影响是直播场景的重要不确定性 | "竞品主播是否同时在打价格战"被列为非线性影响因素 |
| 自身打折效果强于竞品影响 | 行业常识：忠实用户更受品牌自身促销驱动 |

**经济学理论支撑**：替代品交叉弹性（Cross-Price Elasticity）。竞品降价 → 消费者转向替代品 → 自身需求下降。系数 < 1 反映品牌忠诚度的缓冲作用。

---

### 规则 5：主播影响力

**生成公式**：
```
anchor_effect = 0.3 + anchor_fans / 12000
```

| 主播量级 | 粉丝量（万） | 权重大致 | 业务含义 |
|---|---|---|---|
| 头部（薇娅/李佳琦级） | 8,000 | ≈ 0.97 | 几乎可独立带动品类销量 |
| 腰部 | 3,000 | ≈ 0.55 | 有一定影响力，需配合好品 |
| 尾部 | 500 | ≈ 0.34 | 主要靠货品本身竞争力 |

| 访谈依据 | 访谈原话 |
|---|---|
| 主播粉丝量级差异巨大 | "粉丝量级 5000 万到 1 亿" |
| 大主播带货能力远超小主播 | 访谈描述头部主播"单场可卖 1 个亿"、"几十万套产品"，小主播无法企及 |
| 需拉取主播历史表现评估 | "拉取该主播过去 3 年在同类目（美妆/食品）的销售额、转化率、客单价" |

**逻辑**：`0.3` 是基础销量（没有主播光靠货品也能卖），`粉丝/12000` 确保 8000 万粉丝接近 1.0 权重但不超过 1.0，避免主播因素完全主导。

---

### 规则 6：平台推流效应

**生成公式**：
```
traffic_effect = 1 + platform_traffic / 200
节假日平台推流 +20（上限 100）
```

| 访谈依据 | 访谈原话 |
|---|---|
| 平台流量分配无法预知 | "平台算法分配的公域流量大小（抖音突然给大曝光）" |
| 百亿补贴等活动加大推流 | "平台活动叠加导致预测偏差 ±30%" |
| 推流力度变化是决策滞后的原因 | "平台推流力度变化等市场信号未纳入预测模型" |

**参数说明**：推流指数范围 10-80（日常）→ 30-100（大促），对应销量加成 1.05~1.50。保守估计，因为平台的真实流量分配是黑盒。

---

### 规则 7：直播日脉冲效应（核心特征）

**生成公式**：
```
if is_live_day:
    pulse_base = rand(5, 50)
    pulse_multiplier = pulse_base × (anchor_fans / 4000 + 1) / 2
    pulse_multiplier = clip(pulse_multiplier, 5, 50)
    daily_sales *= pulse_multiplier
```

| 参数 | 说明 |
|---|---|
| `rand(5, 50)` | 基础脉冲倍率范围 |
| `anchor_fans / 4000` | 粉丝越多倍率越高（4000 万是中位锚点） |
| `+ 1 / 2` | 归一化使中位主播 ≈ 基础倍率，大主播拉高、小主播压低 |
| `clip(5, 50)` | 保护上下限，不超出访谈中的极端区间 |

| 访谈依据 | 访谈原话 |
|---|---|
| 直播日销量暴增 | "单场直播可能瞬间卖掉 1 个亿"."日发 5 万变 50 万" |
| 大主播脉冲更强 | "头部主播粉丝量级 5000 万~1 亿"对应超高转化 |
| 脉冲不是固定的，波动极大 | "预估卖 5000 万结果爆了 1 个亿"，"预估 1 个亿结果只卖 2000 万" |

---

### 规则 8：随机噪声（模拟不可观测因素）

**生成公式**：
```
daily_sales *= rand(0.85, 1.15)
```

| 访谈依据 | 访谈原话 |
|---|---|
| 存在无法建模的随机因素 | "主播当天话术状态或突发舆论事件" |
| 明星效应难以量化 | "梅西代言第二天超市销量变化，但这种相关性极难量化" |
| 预测有上限 | "影响因素太多，能猜中 60% 就不错了" |

**方法论意义**：随机噪声模拟不可观测混杂因子，确保模型不是在"背公式"，而是学习真实场景中信号+噪声混合的规律。

## 三、数据特征字段一览

| 字段名 | 类型 | 含义 | 是否作为特征 |
|---|---|---|---|
| `date` | datetime | 日期 | ❌（仅索引） |
| `sales` | float | 实际销量（目标变量 y） | 🎯 目标 |
| `price` | int | 商品售价（59-199元） | ✅ |
| `discount` | float | 折扣力度（0.1-1.0） | ✅ |
| `is_holiday` | int | 是否大促节日 | ✅ |
| `is_weekend` | int | 是否周末 | ✅ |
| `anchor_fans` | float | 主播粉丝量（万） | ✅ |
| `anchor_gmv_7d` | float | 主播近7天场均GMV（万） | ✅ |
| `platform_traffic` | float | 平台推流指数（0-100） | ✅ |
| `competitor_discount` | float | 竞品同期折扣 | ✅ |
| `is_live_day` | int | 是否直播日 | ❌（仅用于数据生成和验证，不作为特征输入） |

> **重要**：`is_live_day` **不入模**。模型需要从价格、折扣、推流等信号中"推断"出直播日的销量变化，而不是直接被告知。这模拟了真实场景——供应链做预测时也不知道"哪天直播效果好"。

## 四、方法论的学术定位

### 为什么合成数据是可接受的研究方法

1. **隐私与合规**：企业涉密数据不可外泄，合成数据是学界和工业界的标准替代方案（参考：差分隐私、GAN 生成）
2. **可控实验**：真实数据混杂大量噪声和缺失，合成数据可精确控制变量，做消融实验
3. **极端场景覆盖**：真实 200 天可能只有 1-2 个爆单日，合成可保证信号充足
4. **可复现性**：固定随机种子（`np.random.seed(42)`）确保任何人运行得到相同结果

### 对比真实数据集的优势与局限

| | 优势 | 局限 |
|---|---|---|
| vs 真实数据 | 逻辑透明、可复现、无隐私问题 | 可能遗漏真实场景中的复杂交互 |
| vs 随机生成 | 有业务规则支撑、统计特征与访谈一致 | 规则本身依赖受访者经验（可能存在偏差） |
